# NEU-DET 钢铁表面缺陷检测知识库

## 文档用途

本文档用于本项目的 RAG 知识库，服务于钢铁表面缺陷检测、NEU-DET 数据集说明、模型训练、推理结果解释和常见问题回答。

回答问题时，优先依据本文档和当前项目实际返回的任务、模型、数据集、检测结果；不要把训练指标或检测结果之外的推测当成事实。

## 一、NEU-DET 数据集概览

NEU-DET 是东北大学（Northeastern University）钢铁表面缺陷数据集，面向热轧钢带表面缺陷研究。公开资料通常描述其包含 1800 张灰度图像，共 6 类缺陷，每类 300 张；常见原始图像尺寸为 200 × 200 像素。检测任务版本带有缺陷类别和缺陷位置标注。

NEU-DET 的主要用途是：

1. 训练和评估钢铁表面缺陷检测模型。
2. 验证目标检测数据读取、标注转换、数据增强和推理流程。
3. 比较不同模型或不同训练参数在统一数据上的表现。
4. 为本项目的知识库问答提供缺陷类别、数据集和检测流程背景。

NEU-DET 是实验和基准数据集，不等同于实际生产线数据。生产现场可能存在光照、材质、速度、相机、分辨率、背景和缺陷尺度变化，因此在 NEU-DET 上的结果不能直接代表现场质量。

## 二、六类缺陷名称与检索关键词

### 1. Crazing（Cr）：龟裂、裂纹状缺陷

英文关键词：crazing, Cr, crack-like defect。

中文关键词：龟裂、裂纹、网状裂纹、细长裂纹、裂纹状纹理。

识别提示：通常表现为细长、分叉或网状的裂纹纹理。不要仅凭“细线”直接判定为龟裂，还要结合纹理连续性、分布形态和模型置信度。

### 2. Inclusion（In）：夹杂

英文关键词：inclusion, In, embedded inclusion。

中文关键词：夹杂、夹杂物、嵌入异物、内部异物。

识别提示：通常表现为局部异质区域或不规则暗纹理。夹杂与斑块、轧入氧化皮在低对比度图像中可能相似，需要结合形状、边界和上下文判断。

### 3. Patches（Pa）：斑块、斑痕

英文关键词：patches, Pa, patch defect。

中文关键词：斑块、斑痕、块状缺陷、局部斑状区域。

识别提示：通常表现为面积较大的块状或片状纹理变化。应关注区域边界、内部纹理和与正常钢面之间的对比度。

### 4. Pitted surface（PS）：麻点、点蚀表面

英文关键词：pitted surface, PS, pit, pitting。

中文关键词：麻点、点蚀、凹坑、坑状缺陷、点状缺陷。

识别提示：通常表现为一个或多个局部点状、坑状或暗色区域。小目标、低分辨率和噪声会增加漏检风险。

### 5. Rolled-in scale（RS）：轧入氧化皮

英文关键词：rolled-in scale, RS, scale defect, oxide scale。

中文关键词：轧入氧化皮、氧化皮、轧入皮、条带状氧化皮。

识别提示：通常与轧制过程中的氧化皮相关，可能呈条带状、片状或不规则连续区域。它与斑块、夹杂的外观可能重叠，不能只依赖颜色判断。

### 6. Scratches（Sc）：划痕

英文关键词：scratches, Sc, scratch defect。

中文关键词：划痕、擦伤、线状划伤、表面刮痕。

识别提示：通常表现为细长线状纹理，可呈水平、垂直或倾斜方向。要区分真实划痕与图像噪声、边缘、压缩伪影或龟裂纹理。

## 三、缺陷识别的通用原则

1. 先确认任务类型：单张图片、批量图片、ZIP 图片包或视频检测。
2. 检查模型和检测场景是否正确，确认使用的是目标场景的默认模型或明确选择的模型版本。
3. 结合类别、检测框位置、置信度、目标数量和原图共同判断，不要只看类别名称。
4. 低置信度结果应标记为疑似结果，建议人工复核，不应直接作为质量判定。
5. 训练集、验证集和测试集应保持类别分布合理，避免同一图像或高度相似图像泄漏到多个集合。
6. 数据集标签、类别名称和模型类别顺序必须一致；类别顺序不一致会导致检测框类别解释错误。
7. 训练数据与生产现场存在域差异时，应补充现场样本、重新标注并进行针对性验证。

## 四、本项目中的数据集和训练流程

本项目支持训练数据集上传、数据集校验、训练任务创建、训练进度监控和训练结果查看。推荐流程如下：

1. 准备包含图像和标注的数据集压缩包，确认类别名称、标注格式和目录结构符合项目要求。
2. 在文件查看或训练页面上传 ZIP 数据集。
3. 等待后端完成解压、校验和数据集准备，只有状态为“可训练”或 `ready=true` 的数据集才可用于训练。
4. 创建训练任务，选择检测场景、数据集、模型规格、训练轮数、图像尺寸、批大小、优化器和设备。
5. 训练过程中查看任务状态、当前轮次、进度、损失和评估指标。
6. 训练完成后检查模型文件、训练指标和验证结果，再决定是否将模型版本设为默认检测模型。
7. 使用独立测试图片或测试集进行检测验证，不要直接用训练样本证明模型泛化能力。

项目当前界面提供 YOLO11n、YOLO11s、YOLO11m、YOLO11l 和 YOLO11x 等模型规格选项。模型选择应根据速度、显存、图像分辨率、目标大小和精度需求决定：小模型通常更快，大模型通常需要更多计算资源并可能获得更强的特征表达能力，但最终效果必须以实际验证集和测试集为准。

## 五、本项目中的检测流程

### 单图检测

上传一张测试图片，选择检测场景和模型，点击开始检测。结果应至少关注：检测状态、检测框、缺陷类别、置信度、目标数量和处理耗时。

### 批量图片或 ZIP 检测

确认压缩包内文件格式和图片数量，开始检测后等待任务完成。批量结果中的成功数量、失败数量和失败原因应分开查看；单张失败不代表整个模型或后端服务必然失败。

### 视频检测

视频检测会按配置抽取或处理帧。需要同时关注视频任务状态、已处理帧数、检测目标数量、总耗时和失败信息。视频中的运动模糊、反光、曝光变化和重复帧可能影响结果。

## 六、模型结果解释规范

当用户询问“检测到了什么”时，回答应优先包含：

- 缺陷类别的中文名和英文名/缩写。
- 检测目标数量。
- 置信度或置信度范围（如果接口返回）。
- 检测框或缺陷区域位置（如果接口返回）。
- 是否需要人工复核。

当用户询问“为什么检测失败”时，先区分：

1. 文件上传失败：检查文件格式、大小、路径和网络连接。
2. 数据集校验失败：检查目录结构、图像与标签是否匹配、类别配置和标注格式。
3. 模型加载失败：检查模型版本、文件是否存在、默认模型配置和后端服务状态。
4. 推理失败：检查图片编码、图像尺寸、设备、显存/内存和后端日志。
5. 结果为空：不能直接判定为“没有缺陷”，还要检查置信度阈值、模型类别、图像质量和模型是否适用于当前场景。

管理员可以在管理中心的“知识库管理”区域上传 TXT、MD、PDF 或 DOCX 文档。上传后后端会执行：对象存储、文本解析、文本分块、Embedding 向量化和 pgvector 入库。文档状态为 `indexed` 时，才表示可以参与知识库检索。

## 八、常见误区

1. “检测框数量为 0”不等于“图像绝对没有缺陷”。可能是置信度阈值过高、模型不匹配、图像质量不足或缺陷不在训练分布内。
2. “训练任务完成”不等于“模型质量合格”。还需要查看验证指标、测试集结果和现场样本表现。
3. “类别名称相似”不等于“类别相同”。例如龟裂、划痕、夹杂和斑块在低质量图像中可能混淆。
4. 不要使用格式化时间文本比较任务先后，应使用后端原始时间戳。
5. 不要把系统文档、个人文档和临时测试文档混用；系统文档会对所有有权限的用户提供检索上下文。
